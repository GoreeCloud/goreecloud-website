How GoreeCloud works

One platform. Multiple layers of control.

GoreeCloud is organized as a layered personal-cloud platform. Approved family devices reach self-hosted services through controlled access paths, while data protection and recovery remain separate responsibilities. Individual technologies can change without giving up ownership of the information they protect.

01

Private Access

Approved users and devices reach only the GoreeCloud services they are authorized to use through controlled private connectivity.

02

Self-Hosted Applications

Family-facing services provide files, photos, media, credentials, knowledge, documents, and messaging without making any single application the platform itself.

03

Storage & Data

Important information stays under direct GoreeCloud control so it can remain organized, portable, and transferable between applications and future systems.

04

Security & Isolation

Access boundaries, workload separation, least privilege, and privacy-by-default controls limit unnecessary exposure between users, services, and administrative systems.

05

Backup & Recovery

Independent backup and recovery layers protect the information behind the services so failures, migrations, and technology changes do not become permanent data loss.

GoreeCloud principle: Systems are replaceable. The information they protect is not.

Platform foundation

The technology underneath GoreeCloud.

GoreeCloud is operated through separate infrastructure layers rather than a single application. Each layer has a defined role across virtualization, operating systems, containers, private networking, DNS, HTTPS publication, monitoring, notifications, and private search. The technologies can change over time without changing GoreeCloud's purpose.

Planned Local

Virtualization Foundation

Proxmox VE

The planned bare-metal virtualization foundation for GoreeCloud's locally owned servers, providing clear virtual-machine boundaries for storage, family services, infrastructure, security, automation, and AI workloads.

Role: Virtualization, workload separation, and host-level resource control.

Active + Standard

Linux Foundation

Debian 13

Debian 13 runs the current GoreeCloud server foundation and is the standard Linux operating system selected for future GoreeCloud virtual machines unless a documented requirement calls for another platform.

Role: Stable, lightweight, and maintainable Linux operating-system layer.

Active

Container Platform

Docker

Docker runs many GoreeCloud application and infrastructure services in portable, reproducible containers. In the planned local architecture, Docker remains inside the virtual machine responsible for each workload category.

Role: Container execution, dependency isolation, and portable service deployment.

Active

Private Networking

NetBird

NetBird is GoreeCloud's fully self-hosted encrypted private-networking and secure remote-access layer, connecting approved users, devices, servers, and future virtual machines through explicit access policies.

Role: Private connectivity, device identity, and policy-controlled remote access.

Active

DNS Filtering

AdGuard Home

AdGuard Home is GoreeCloud's client-facing DNS filtering and policy layer, applying approved filtering rules and private DNS rewrites for authorized devices while keeping DNS control under GoreeCloud administration.

Role: DNS filtering, client policy enforcement, and private hostname resolution.

Active

HTTPS Gateway

Caddy

Caddy is GoreeCloud's controlled reverse proxy and HTTPS gateway, providing approved domain-based routing, TLS termination, certificate management, and controlled access to web services.

Role: Reverse proxying, HTTPS publication, TLS, and service routing.

Active

Notifications & Alerts

ntfy

ntfy provides GoreeCloud with a centralized, self-hosted notification path for operational messages from approved infrastructure services to authorized web and mobile clients.

Role: Infrastructure notifications, alert delivery, and centralized operational messaging.

Active

System Monitoring

Beszel

Beszel provides operational visibility into the GoreeCloud server foundation, supporting ongoing review of system and container health and resource usage.

Role: Host monitoring, container visibility, and resource-health awareness.

Active

Availability Monitoring

Uptime Kuma

Uptime Kuma verifies the availability and health of GoreeCloud applications and infrastructure through approved public and internal service endpoints.

Role: Service availability checks, endpoint monitoring, and operational status visibility.

Active

Private Search

SearXNG

SearXNG gives GoreeCloud a privately administered metasearch service that provides a consistent search interface while reducing direct dependence on a single commercial search provider.

Role: Private metasearch, controlled internet research, and search-provider independence.

Current → target: GoreeCloud currently uses Debian 13, Docker, NetBird, AdGuard Home, Caddy, ntfy, Beszel, Uptime Kuma, and SearXNG as active parts of its current server foundation. The long-term design moves primary workloads to locally owned Proxmox hosts while preserving portable services, private access, monitoring, notifications, search, and controlled DNS and HTTPS publication.

Logos are used only to identify their respective technologies and remain the property of their respective owners. This is a representative foundation, not a complete public infrastructure inventory.

Expanding the platform

Home automation, private security, and local AI.

GoreeCloud's target local architecture adds dedicated workload boundaries for smart-home automation, surveillance, and artificial intelligence. These capabilities are intentionally separated from family applications and core infrastructure so each can be secured, maintained, scaled, backed up, and recovered according to its own requirements.

HA Planned

Home Automation

Home Assistant

Home Assistant will provide the household automation and orchestration layer for approved smart devices, sensors, scenes, dashboards, notifications, and future voice or AI integrations.

Current status: Architecture defined, not yet deployed. The target design uses a dedicated Home Assistant OS virtual machine in the future local Proxmox environment.

  • Dedicated Home Assistant OS VM
  • Smart-device orchestration and household dashboards
  • Independent backup, recovery, and network boundaries
FR Planned

Video Security

Frigate

Frigate will serve as the local video-surveillance and object-detection platform, handling approved camera streams, event detection, recordings, retention, and security alerts.

Current status: Planned, not yet deployed. Frigate is assigned to a dedicated Security VM so surveillance workloads remain isolated from family applications, infrastructure administration, and AI services.

  • Local camera stream processing and object detection
  • Dedicated surveillance storage and retention controls
  • Restricted administrative and recording access
AI Planned

Local Intelligence

Local AI

GoreeCloud is being designed to run private AI locally through complementary services: Ollama for model execution, Open WebUI for general conversations, and AnythingLLM for persistent document knowledge and retrieval.

Current status: The core local-AI stack is planned and not yet installed. SearXNG is already active today and is intended to provide controlled current-internet research to future local AI workflows.

  • Ollama local model execution
  • Open WebUI private conversational interface
  • AnythingLLM knowledge workspaces and RAG

Status note: “Planned” means the role and target architecture are documented, but the production workload is not currently deployed. GoreeCloud will only promote these services to active status after the required local infrastructure, access controls, monitoring, backup, and recovery paths are implemented and validated.

Software & development

GoreeCloud is becoming software, too.

GoreeCloud uses mature open-source applications wherever they already solve the problem well, maintains forks when a strong upstream foundation needs GoreeCloud-specific capabilities, and develops original software when a purpose-built application provides meaningful long-term value.

Research Library — In Development GoreeCloud Research Library is the first GoreeCloud-maintained upstream fork. Built from Linkding, it is being extended from bookmark management into a private research-source, verification, preservation, and retrieval platform with the product message “Curate. Verify. Preserve.” View the public Research Library repository →
GoreeCloud Manager — In Development GoreeCloud Manager is the first native GoreeCloud application: an original management and operational console being developed specifically for the platform. Its current v0.1 development work provides least-privilege, read-only visibility for NetBird, Healthchecks, Uptime Kuma, Beszel, and Kopia protection state while specialized services remain authoritative for their own operations. View the public GoreeCloud Manager repository →
Memos — Early Development GoreeCloud Memos is a newly established fork of the open-source Memos project for fast, Markdown-native, self-hosted note capture. It adds a lightweight quick-capture notes project alongside GoreeCloud's broader knowledge-management plans while keeping the source and future customization path under GoreeCloud control. View the public Memos repository →

Open source first. Fork when justified. Build original software when GoreeCloud itself requires a distinct product.

What is GoreeCloud?

More than a homelab.

GoreeCloud is a privacy-first, self-hosted personal and family cloud platform built to preserve a family's digital life over the long term.

The purpose is not to preserve any single server, application, vendor, or architecture forever. The purpose is to preserve the information entrusted to those systems — including memories, records, knowledge, credentials, and personal data — so it remains accessible, portable, recoverable, and understandable as technology changes.

PrivacyProtection is a design requirement, not an optional setting.
OwnershipThe rightful owner retains control over their information.
Open SourceOpen-source, self-hosted software is preferred wherever practical.
RecoverabilityBackups and restoration are part of the architecture.
IndependenceCritical information should not depend on a single provider.
PreservationImportant information should survive technology changes.

Built deliberately from the beginning.

GoreeCloud started in 2026 as a plan for a private, self-hosted environment and quickly grew into a structured personal cloud platform.

The first GoreeCloud planning work begins with a goal of replacing subscription-based services with greater privacy, control, and data ownership.

2026 →

The project expands into a governed platform with defined architecture, security policies, standards, procedures, recovery requirements, and long-term goals.
