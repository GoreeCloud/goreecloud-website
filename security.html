Responsible security reporting

I welcome good-faith reports about security vulnerabilities affecting public-facing GoreeCloud properties and publicly available software. Wardveil Security is the GoreeCloud security identity and presentation layer; underlying technical controls and evidence remain authoritative.

What to include

A useful report should contain enough detail to reproduce the issue safely.

  • The affected public GoreeCloud URL, repository, application, or version.
  • A clear vulnerability description and likely impact.
  • Minimal reproducible steps that avoid unnecessary harm.
  • Relevant request, response, log, screenshot, or proof-of-concept details with sensitive data removed.
  • Any remediation idea or mitigating condition already identified.

Testing boundaries

This policy does not authorize testing of private family infrastructure, private services, accounts, devices, internal networks, administrative interfaces, credentials, or non-public data. A public security policy is not permission to cross an access-control boundary.

  • Do not access, retain, modify, or disclose data that does not belong to you.
  • Do not perform destructive testing, denial-of-service activity, social engineering, credential attacks, or service disruption.
  • Do not use high-volume automated testing that could materially degrade a service.
  • Do not publicly disclose exploit details before there has been a reasonable opportunity to remediate the report.

Wardveil identity boundary

Wardveil gives security-facing experiences a consistent identity but does not replace the controls that establish whether a system is secure, patched, authenticated, authorized, isolated, backed up, or recoverable. This website makes no blanket Wardveil protection assurance. Any explicit Wardveil protection status requires a defined scope and current Wardveil-scoped evidence. Privacy Shield privacy status does not become Wardveil security status merely because both appear together.

How reports are handled

I will review credible reports and prioritize remediation according to impact, exploitability, exposure, and safety. GoreeCloud does not currently offer a bug bounty or guaranteed response timeline. This guidance does not create authorization to access systems, accounts, or data.
