Native ownership.

Existing complete upstream applications and forks may remain temporarily for migration, continuity, compatibility, testing, or reference, but they are not permanent GoreeCloud application architectures. Explore the portfolio

The current directory reflects the August 27 portfolio: GoreeCloud AI is the first-party local-model and intelligence workspace; GoreeCloud Code is the first-party developer/source-control platform with Forgejo as its initial replaceable infrastructure foundation; Documents, Messenger, Gateway, Quill, and Mesh are represented alongside the broader native-suite transition. Transitional upstream provenance stays visible where it still matters, but every application card is interpreted against the mandatory native end state.

Development model

Native is the required end state.

Every GoreeCloud application must be original GoreeCloud-owned software at the product and application layer. Mature libraries, standards engines, codecs, rendering engines, cryptographic primitives, operating-system/runtime components, and comparable foundations may remain when replacing them would materially increase technical risk. Transitional upstream product code stays identified as transitional.

Release integrity

Labels never outrun evidence.

Public source, a successful build, active development, a release candidate, or a platform identity does not automatically establish production acceptance or protection. Stable applications must satisfy current Glaze UI 1.5, Privacy Shield, Wardveil Security, and Everkeep requirements for their supported scope, with applicable current acceptance evidence. Mesh may coordinate that evidence, but it cannot create or upgrade the authoritative state.
